# `/v1` API contract

The local contract is intentionally small and versioned. JSON errors use `{ "error", "message", "details" }` and never include secret values.

| Method | Path                             | Purpose                                             |
| ------ | -------------------------------- | --------------------------------------------------- |
| GET    | `/metrics`                       | Protected Prometheus-compatible HTTP counters       |
| GET    | `/health`                        | Process liveness                                    |
| GET    | `/ready`                         | Dependency readiness                                |
| POST   | `/v1/builds`                     | Create a validated build job                        |
| POST   | `/v1/build-sources`              | Store a validated content-addressed source snapshot |
| POST   | `/v1/build-sources/upload-plan`  | Create a short-lived direct R2 source upload URL    |
| POST   | `/v1/build-sources/complete`     | Verify and finalize a direct source upload          |
| POST   | `/v1/builds/:id/run`             | Execute through the selected provider in local mode |
| POST   | `/v1/builds/:id/report`          | Persist a worker state/log/artifact report          |
| GET    | `/v1/builds/:id`                 | Inspect a build                                     |
| GET    | `/v1/worker-builds/:id`          | Load one build for its bound worker                 |
| GET    | `/v1/worker-builds/:id/source`   | Load source for its bound worker                    |
| POST   | `/v1/worker-builds/:id/artifact` | Upload binary artifact for its bound worker         |
| POST   | `/v1/ota/releases`               | Publish a signed, policy-gated OTA release          |
| POST   | `/v1/ota/rollback`               | Point a channel at a previous compatible release    |
| GET    | `/v1/ota/public-key`             | Return the public key needed by native OTA clients  |
| GET    | `/v1/ota/check`                  | Return the current eligible release or `null`       |
| POST   | `/v1/submissions`                | Submit a hashed artifact through a provider adapter |
| POST   | `/v1/workers`                    | Register an organization-owned worker               |
| GET    | `/v1/workers`                    | List workers for an organization                    |
| POST   | `/v1/workers/:id/heartbeat`      | Refresh a worker heartbeat                          |
| POST   | `/v1/workers/:id/drain`          | Stop assigning new jobs to a worker                 |
| POST   | `/v1/workers/:id/revoke`         | Permanently revoke a worker                         |
| POST   | `/v1/tokens`                     | Create a scoped API token; secret returned once     |
| GET    | `/v1/tokens`                     | List redacted tokens for an organization/project    |
| DELETE | `/v1/tokens/:id`                 | Revoke a token                                      |

The server uses JSON, memory and filesystem adapters for local development. The production Compose overlay selects PostgreSQL, Redis and external R2 artifact mode with `LYNXSHIP_DATABASE_DRIVER`, `LYNXSHIP_QUEUE_DRIVER`, `LYNXSHIP_STORAGE_DRIVER=r2`, `DATABASE_URL`, `REDIS_URL` and the `R2_*` variables; `/ready` actively probes all selected durable backends and returns `503` when one is unavailable. Production also requires `LYNXSHIP_REQUIRE_AUTH=1`, `LYNXSHIP_TOKEN` and a stable `LYNXSHIP_CREDENTIAL_MASTER_KEY`; `LYNXSHIP_RATE_LIMIT` enables a bounded fixed-window limiter. Build creation accepts an optional `idempotencyKey`; retrying the same organization/project request returns the original job instead of creating a duplicate. Redis-backed builds are published to a Redis Stream and consumed by the worker runtime with at-least-once acknowledgement and reclaim of abandoned messages. The CLI owns the Cloudflare R2 S3 credentials, uploads the signed binary directly, and sends only immutable artifact metadata and a temporary download URL to `POST /v1/artifacts`. The bootstrap token is an operational baseline, not a complete hosted identity service; rotate it outside the repository and use a separate tenant-aware token store before opening the API to multiple customers.

Worker routes use dedicated scopes rather than the general build scope:
`worker:manage` registers, drains and revokes workers; `worker:heartbeat`
refreshes liveness; and `worker:report` is used by build agents. A production
agent should create a short-lived token with `worker:report` and its
`workerId`, then include `x-lynxship-worker-id` on every build report. The API
checks the token binding, worker status, organization and build platform before
accepting the report. Repeated reports for the current state are idempotent so
an at-least-once queue retry cannot create an invalid transition.

`GET /v1/worker-builds/:id` requires `worker:report` and the
`x-lynxship-worker-id` header. A bound worker token can load only a build for
its own worker's organization and platform; revoked workers are rejected.

`POST /v1/build-sources` accepts `{ projectId, organizationId, dataBase64 }`.
The data must be a canonical JSON source snapshot generated by the CLI. The
API validates every file digest, manifest digest, path and credential exclusion
before storing it and returns a `{ key, hash, size, contentType, fileCount }`
reference. `GET /v1/worker-builds/:id/source` requires the same worker header
and serves the snapshot only when the worker is registered for the job's
organization and platform. The worker verifies the returned bytes again before
materializing its disposable workspace. After the executor reaches
`uploading_artifacts`, `POST /v1/worker-builds/:id/artifact` accepts binary
content with the same worker binding, computes SHA-256 server-side and stores
it under a project/build-scoped key. R2 deployments return a short-lived HTTPS
download URL; local filesystem deployments return metadata without pretending
that the object is publicly downloadable.

`/metrics` emits the Prometheus text format with validated metric and label
names. Label values escape backslashes, quotes and line breaks, and malformed
internal metric keys are omitted instead of corrupting the exposition stream.

The OTA check and public-key endpoints are intentionally public read endpoints:
the mobile client has no developer secret. Releases remain signed and asset
URLs remain HTTPS/R2 bearer URLs; protect the publishing endpoint with
`update:write` authentication and rate limits. The rollback endpoint uses the
same `update:write` scope and requires an audit reason for the production
channel. It changes only the channel pointer; it does not delete the release
or its artifact.
